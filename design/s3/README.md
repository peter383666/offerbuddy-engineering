# Sprint 3 Design

Design answers: **how Sprint 3 is specified before and during delivery**.

Organised by reader intent, not by Phase 1/2/3 process order.

| Area | Entry | Status |
| --- | --- | --- |
| Requirements | [requirements/](requirements/) | Frozen baseline published |
| Technical Design | [technical/](technical/) | Frozen baseline published |
| UI/UX | [ui-ux/](ui-ux/) | Approved baseline published |

Source-of-truth order during implementation:

```text
1. Frozen S3 requirements and final scope review
2. Frozen S3 architecture
3. Frozen S3 technical design and API contract
4. Approved S3 UI/UX page specifications
5. Phase 5 implementation planning
6. Implementation evidence and reconciled current-system documentation
```

Later documents may clarify implementation detail but must not silently alter an earlier authoritative domain, security, or data-ownership decision. A genuine contradiction returns to design review.
