# Definition of Done

## Purpose

This Definition of Done establishes the minimum quality standard for work completed in OfferBuddy.

An issue is considered done when:

- Its acceptance criteria are satisfied.
- The implementation builds successfully.
- Relevant automated tests have been added or updated and pass.
- Required linting and static checks pass.
- Continuous integration passes.
- Security, privacy, validation, and failure handling have been considered where relevant.
- Documentation is updated when behaviour, architecture, operation, or decisions change.
- The change has been reviewed through a pull request.
- Review feedback has been resolved.
- The feature branch has been merged into the target branch and can be deleted.

## Exceptions

If an item cannot meet this definition, it must not be silently treated as done. Any accepted exception must be visible in the issue or pull request, include its impact, and identify follow-up work.

## Application

This definition applies to product features, defects, engineering improvements, and documentation changes. Individual issues may add stricter completion criteria.
